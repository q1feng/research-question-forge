# Usage

[Home](../README.md) · [简体中文](../zh/usage.md)

## Without installation

Attach the [complete guide](question-forge-guide.md) and describe observations or ideas, existing material, resources, and this turn's goal. A final title and a long questionnaire are unnecessary. The guide includes all rules. Without file tools, request saveable Markdown. Cloud assistants cannot automatically access local paths; provide the actual files.

## Install the Skill

Copy the complete `research-question-forge-en/` folder into a Skill directory supported by your client, retaining SKILL.md, agents, and references. Do not copy the entry alone. Consult the client's instructions for installation locations and discovery. This package does not change global settings.

Invoke: `Use $research-question-forge-en to work on the current stage with my materials, preserving research decisions and evidence limits.`

The language editions have distinct names and can coexist. If discovery fails, ask the assistant to read the [entry](research-question-forge-en/SKILL.md) and its references, or use the portable guide. No specific model, API key, or other Skill is required.

## Continue existing work

Point to existing files and reuse them. When papers arrive, update affected baselines, claims, and directions rather than appending abstracts. Explain the basis and cost of revisions; implement an explicit choice. Output filenames have no language suffix; use separate directories for bilingual outputs when needed.

Mark missing evidence honestly. A framework, draft, or successful script run is not a research conclusion. Retrieval, analysis, and layout depend on the user's request and available tools.

Maintain research-framework.md by default; add research-comparison.md when useful. Pass formal review or report writing to the workflow of your choice.
